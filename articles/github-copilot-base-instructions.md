GitHub Copilot で Claude Opus 5 や GPT-5.6 系モデルを使用すると、自律性が高まった一方で、さまざまなパターンの自己省察（self-reflection）を繰り返すあまり、必要以上に考えたり、齟齬が生じたりするケースがあります。こうした課題は `thinking effort` を調整することで抑えられる場合もありますが、事前に適切な `thinking effort` を決めることは難しく、最終的にはプロンプト（インストラクション）に指示を追記するケースが多いです。

GitHub Copilot では、`.github/copilot-instructions.md` やワークスペースルートの `AGENTS.md` をインストラクションファイルとして使用できます。これらに記述しておけば、各チャットリクエストに自動的に追加されます。また、インストラクションファイルを生成できる `/init` コマンドも用意されています。

そこで本記事では、筆者が Claude Opus 5 や GPT-5.6 系モデル（特にSol）を使用する中で、`/init`したあとにインストラクションファイルに追記しておいたほうがよいと感じた GitHub Copilot 向けの共通インストラクションを記載しています。基本的には自分用のコピペメモですが、用途に応じて参考にしていただける部分もあるかと思います。今後も随時更新する予定です。

```text
- ユーザーから指定がある場合を除き、アプリケーションは初期開発段階にあるため、後方互換性やデータ移行を考慮する必要はありません。
- 設計ファイルがある場合は設計先行型で開発し、常に設計内容をユーザーと協議し、確定してから実装してください。実装後に仕様変更が生じた際も設計書の変更（再設計）からスタートしてください。
- 与えられたタスクのスコープを勝手に狭めたり、指示されていない MVP を独自に定めたりしないでください。
- ラバーダックを使って、計画→実装→検証→再計画のループを自律的に回してください。与えられたタスクがすべて完了するまで、作業を終了しないでください。
- UI のレイアウト設計では、安直にデータモデルのプロパティを並べるのではなく、データモデルとユースケースから UI が提供すべき情報構造を設計し、必要十分な情報を適切なタイミングで画面に表示してください。
- UI が関係する実装では、スクリーンショットなどで実際の表示を確認し、合否を判定してください。
- 常にタスクを細分化し、サブエージェントや複数のセッションを用いた並列実行を検討してください。
```
